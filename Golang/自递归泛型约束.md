# Go Self-Recursive Generic Constraint（自递归泛型约束）学习文档

> 适用读者：已经会用 Go 基础泛型（`[T any]`、`constraint interface`），但看到  
> `[T SomeInterface[T]]` 这种“接口里又出现自己”的写法时一头雾水的人。

---

## 1. 一句话定义

**Self-Recursive Generic Constraint（自递归泛型约束）** 是指：

> 一个泛型类型参数 `T` 的约束本身，又用 `T` 去实例化了自己。

典型形式：

```go
func Foox T
```

或者：

```go
type SomeInterface[T any] interface {
    DoSomething() T
}
```

它的作用是：

> **让“具体类型”在实现接口时，方法参数 / 返回值必须是“它自己”**，而不是接口、也不是 `any`。

在类型理论里，这叫 **F-bounded polymorphism（F 界多态）**；在 C++ 里对应 **CRTP（Curiously Recurring Template Pattern）**。

---

## 2. 为什么需要它：传统接口的痛点

### 2.1 传统接口会“吃掉具体类型”

```go
type Cloner interface {
    Clone() Cloner
}

type User struct {
    Name string
}

func (u User) Clone() Cloner {
    return User{Name: u.Name + "_copy"}
}
```

调用时：

```go
u := User{Name: "tom"}
c := u.Clone()
// c 是 Cloner，不是 User
_ = c.(User) // 必须类型断言，运行时才可能 panic
```

❌ 方法链断裂  
❌ 具体类型信息丢失  
❌ 编译期类型安全变弱  

---

### 2.2 想要的是这件事

```go
User.Clone() → User
Order.Clone() → Order
OCRRequest.SetURL() → OCRRequest
```

也就是：

> **“返回我和我自己的类型一模一样的东西”**

Go 泛型出现前，这事没法在接口层干净表达。

---

## 3. 自递归泛型约束长什么样

### 3.1 定义泛型接口

```go
type preciseSceneImageRequest[T any] interface {
    SetURL(url string) T
    SetBody(body io.Reader) T
}
```

注意：

- `T` 是类型参数
- 方法返回的是 `T`
- 但此时**还没形成递归约束**，它只是一个“泛型接口”

---

### 3.2 在泛型函数里“递归使用”

```go
func withPreciseSceneImage[T preciseSceneImageRequest[T]](
    request T,
    req *ocr.ProviderRequest,
) T {
    if req.ImageSource == ocr.ImageSourceFilePath {
        return request.SetURL(req.ImageURL)
    }
    return request.SetBody(bytes.NewReader(req.Image))
}
```

关键在这一句：

```go
[T preciseSceneImageRequest[T]]
```

读作：

> T 必须实现 `preciseSceneImageRequest[T]`，  
> 并且接口里的 `T` 就是“实现该接口的具体类型 T 自己”。

---

## 4. 编译器在检查什么（重点）

假设你有：

```go
type OCRRequest struct {
    URL  string
    Body io.Reader
}

func (r OCRRequest) SetURL(url string) OCRRequest {
    r.URL = url
    return r
}

func (r OCRRequest) SetBody(b io.Reader) OCRRequest {
    r.Body = b
    return r
}
```

那么：

```go
OCRRequest 实现了 preciseSceneImageRequest[OCRRequest]
```

所以可以代入：

```go
T = OCRRequest
preciseSceneImageRequest[T] = preciseSceneImageRequest[OCRRequest]
```

✅ 编译通过  
✅ `SetURL / SetBody` 返回的是 `OCRRequest`  
✅ 方法链不会退化成接口  

---

## 5. 如果“不递归”会怎样

### ❌ 写法 A：返回接口

```go
type Setter interface {
    SetURL(string) Setter
}
```

问题：

- 返回的是接口
- 失去具体类型
- 不能继续调用具体类型独有方法

---

### ❌ 写法 B：用 `any`

```go
type Setter interface {
    SetURL(string) any
}
```

问题：

- 调用方必须类型断言
- 运行时风险
- 泛型意义丧失

---

### ❌ 写法 C：不用泛型

```go
func WithImage(r OCRRequest) OCRRequest
func WithImage2(r IDCardRequest) IDCardRequest
```

问题：

- 每多一种 Request 就多一套函数
- 无法抽象“五种 OCR 请求共有能力”

## 6. 典型使用场景

### ✅ Builder / Fluent API

```go
type Builder[T any] interface {
    WithName(string) T
    WithAge(int) T
}
```

---

### ✅ Clone / Prototype

```go
type Cloner[T any] interface {
    Clone() T
}
```

---

### ✅ 同类型比较 / 排序

```go
type Ordered[T any] interface {
    Less(T) bool
}
```

（Go 1.26 起允许 `Ordered[T Ordered[T]]` 这种更直接的形式）

---

### ✅ 你的场景：多类 SDK Request 共享设置逻辑

```go
type (
    OCRRequest      struct{ ... }
    IDCardRequest   struct{ ... }
    LicenseRequest  struct{ ... }
)

// 它们都：
//   SetURL(string) 自身
//   SetBody(io.Reader) 自身

func withImage[T preciseSceneImageRequest[T]](req T, p *ProviderRequest) T
```

✅ 一个函数  
✅ 多种 Request  
✅ 返回具体类型  
✅ 编译期校验

## 7. 心智模型（非常重要）

你可以把它想成：

> **“接口不是用来‘抹平类型’的，而是用来‘要求类型和自己玩’的。”**

普通泛型：

```go
[T any]
// T 是“某个类型”
```

自递归约束：

```go
[T Iface[T]]
// T 是“一个知道怎么产生 T 自己的类型”
```

---

## 8. 常见误解

### ❌ 误解 1：这是无限递归？

不是。

递归的是**类型关系**，不是运行时代码：

```
T implements Iface[T]
Iface[T].Method() returns T
```

编译器在有限步内就能判定。

---

### ❌ 误解 2：接口定义本身就“自递归”了？

不是。

```go
type Iface[T any] interface {
    Foo() T
}
```

这本身**不是递归约束**。

只有在这里才是：

```go
func F[T Iface[T]](x T)
```

👉 **递归发生在“把接口用作约束，并用 T 实例化它”的时候。**

---

### ❌ 误解 3：所有 Builder 都必须这么写？

不是。

- 只有 1 个类型 → 直接写方法
- 少量类型 → 复制函数也行
- 多类型 + 要共用泛型逻辑 → 才值得用自递归约束

---

## 9. 最小可运行模板（可直接抄）

```go
type Setter[T any] interface {
    SetURL(string) T
    SetBody(io.Reader) T
}

func ApplyImage[T Setter[T]](r T, url string, body io.Reader) T {
    if url != "" {
        return r.SetURL(url)
    }
    return r.SetBody(body)
}

type ReqA struct{ URL string }

func (r ReqA) SetURL(u string) ReqA { r.URL = u; return r }
func (r ReqA) SetBody(io.Reader) ReqA { return r }

type ReqB struct{ URL string }

func (r ReqB) SetURL(u string) ReqB { r.URL = u; return r }
func (r ReqB) SetBody(io.Reader) ReqB { return r }
```

## 10. 什么时候**不要用**

❌ 团队不熟悉泛型  
❌ 只有 1～2 个类型  
❌ API 对外暴露，阅读成本 > 抽象收益  
❌ 为了“看起来高级”而用  

> 自递归约束是**库作者工具**，不是业务代码标配。
